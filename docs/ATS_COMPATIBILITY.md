## Bug fixed in Phase 19C

`ats_registry.detect()` built `host + "/" + path` — since `path` already
starts with `/`, every **path-bearing signature** (e.g. `zoho.com/recruit`)
could never match (double slash). Host-only signatures were unaffected. The
blob is now `host + path`. Found by the new URL-detection tests.

## Sandbox fixtures

`tests/e2e/fixtures/` — 14 local HTML pages (13 platforms + the generic
form). Each covers: required/optional fields, dropdowns, radio groups,
checkboxes, resume upload, validation errors, multi-step navigation (where
the platform uses it) and a confirmation page. Generated by
`scripts/gen_ats_fixtures_19c.py` (except the Phase 18 five).

## What the E2E suite proves per flow

Form detection → field mapping from the verified profile (no invented
values) → file upload → multi-step advance → validation errors block (never
force-advance) → assisted mode never reaches the platform's submit →
authorized mode submits only after the approval gate and records
confirmation evidence → duplicate submission is structurally impossible →
crash/reload resumes from checkpoint. CAPTCHA, MFA, login walls and legal
declarations are never bypassed.

## Live-platform policy

Testing against real ATS platforms requires **authorized test accounts**
which this project does not own. The honest position: sandbox evidence only,
`VERIFIED` reserved and unclaimed. When direct discovery is unavailable for
an India platform, the UI shows an external search link and marks the source
external-only — no fabricated listings.
